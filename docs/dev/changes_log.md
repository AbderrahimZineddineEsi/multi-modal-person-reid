# Behavioural changes v1 -> v2

One section per phase. Format: `- [component] v1: ... -> v2: ... Why: ... (refs: v1_review B#/W#, paper)`.

## P3: identity association, consolidation, prototypes, search, analytics

Scope: `src/reid/identity/`, `src/reid/search.py`, `src/reid/analytics.py`, the `reid search` CLI command, additive `storage/db.py` (schema v2) and the `association` / `consolidation` / `search` config sections. Papers: **Casao** = Casao et al., Sensors 23(5):2662 (2023); **AM&B** = Al Muzaddid & Beksi, arXiv:2510.17043.

### Behavioural changes

- [gallery] v1: a frame-level gallery, every frame of a confidently assigned track was inserted (no gate), the O(N^2) pruner ran every frame, and the entropy/redundancy cost was `0.5/0.5` -> v2: tracklet samples (<= 16, best quality first) go through Casao's diversity gate `D_i(x) >= D(C_i)` before insertion, and over budget `m = 50` the sample `argmax[gamma*H/log N - (1-gamma)*D_i]` with gamma = 0.6 is dropped; `D(C_i)` is the smallest pairwise distance (Casao Eq. 6, `diversity_ref: min`; `mean` is a stricter option). Why: removes near-duplicate galleries and the per-frame pruning cost. (refs: v1_review 1.6, W3; Casao Eq. 5-10)
- [gallery] v1: entropy normalised by `log(n_classes)` after an earlier `log(emb_dim)` bug -> v2: `log N`, entropy term 0 when N = 1. The paper prints `log(1/N)`, which is negative and would flip the sign; we follow the stated intent (normalise to [0, 1]). (refs: Casao Eq. 10)
- [gallery] v1: centroid weights = pose visibility ratio only -> v2: weights = per-sample quality (visibility x detection confidence, from P2). Why: superset of Casao's visibility weighting. (refs: Casao technique 4)
- [gallery] v1: `_optimize_budget` removed ONE sample per call, so a gallery merged above budget stayed over budget (m6) -> v2: pruning loops until within budget, also after merges (`GalleryBank.merge`). (refs: B7)
- [body decision] v1: softmax temperature 15 on frame embeddings, first assignment sticky for the whole track -> v2: temperature 10 (Casao v = 0.1) applied to the **tracklet** descriptor (quality-weighted mean), plus a sample vote (`sample_vote` = 0.5: at least half of the samples must individually pick the same gid). Cannot-linked gids are removed before the softmax (a single remaining candidate has ratio inf and is accepted on `min_cos`, as in v1). (refs: W2, B3; Casao Sec. 3.3)
- [gallery update] v1: every frame of a track was added to its gid without any check -> v2: verify-before-update, samples are inserted only after a confident assignment; a face-assigned tracklet whose body confidently contradicts the face gid is NOT inserted and records a must-link. (refs: B3; OmniGlimpse-style verify-before-update)
- [face assignment] v1: one face frame >= 0.55 triggered an irreversible gallery/doc merge -> v2: a tracklet needs >= `face_min_obs` = 2 faces (quality-weighted descriptor), best gid >= `face_match` 0.55, a lead of `face_margin` 0.05 over any *different-looking* gid (a competitor that is itself a >= 0.55 face match of the winner is fragmentation of the same person and does not make it ambiguous), and >= 2 of its own faces within 0.55 of the winner's face centroid. Face is a gid assignment for that tracklet only, never a merge. Face vectors are stored only for tracklets with >= `face_min_obs` faces. (refs: B4, B6, B11)
- [constraints] v1: none (a gid could be claimed by two simultaneous people, B4) -> v2: cannot-links: same camera with time overlap > `overlap_tolerance_s`; face conflict (cos < `face_conflict` 0.30, both with accumulated faces); optional topology transit time (`CameraSet.min_transit` > 0 and time gap < it). Must-links: face matches between identities with a margin (see `constraints.must_links`). (refs: B1, B4)
- [UDM] v1: DBSCAN on frame embeddings, min 5 samples, eps 0.15, merge at cos >= 0.85, no k-nearest-centroid test, no flush, scheduled by `frame % 30` (B8, B9) -> v2: DBSCAN (min_samples 1 tracklet, eps 0.15 cosine) on pooled **tracklet descriptors**; a cluster is evaluated at >= 20 samples (Casao l = 20); distance = min over samples of `1 - x.x_j` against the k = 3 most frequent classes among the samples' 3 nearest centroids, new gid if > 0.1 (Casao alpha), else merge into the closest class; cannot-links honoured (distance 2 before DBSCAN + greedy split of each cluster, blocked gids never merge targets); scheduled by pool size (`udm_every` = 20 tracklets) and at `end_camera`; `end_run` flushes the pool (size threshold dropped, distance test kept) so nobody vanishes. (refs: B8, B9, W8; Casao Sec. 3.3)
- [bootstrap] v1: first track minted, otherwise UDM -> v2: while fewer than `bootstrap_q` = 20 identities exist (Casao Q = 20), an unmatched tracklet with >= `bootstrap_min_samples` = 8 samples mints directly, or joins an existing gid at cos >= 0.9 (Casao epsilon). (refs: Casao Sec. 3.3 initialisation)
- [consolidation] v1: retroactive in-memory/DB merge on face match (B4, B5), no repair of fragmentation -> v2: constrained average-linkage agglomerative clustering over gid centroids at `end_run` (threshold 1 - cos = 0.25), face must-links first, cannot-links never violated (also transitively), oldest gid kept, tracklets relabelled with `db.set_gids(source='consolidate')` (history, reversible), galleries unioned and re-pruned, vector labels and prototypes follow. (refs: B4, B5, B6, B7)
- [manual ops] new: `merge_identities`, `split_tracklet` (a persistent `identity_cannot_links` row stops consolidation re-merging it), `rename_identity`, `recluster` (UI). (refs: PLAN 6, admin tab)
- [prototypes] v1: raw `alpha*q + (1-alpha)*dist` (q in 0.4-0.9, dist in 0-0.3, so quality dominated), only in m6 (B12), destructive delete-all + rewrite -> v2: `alpha_fps` with q and dist min-max normalised per step, seeded by the best quality sample, one `rebuild_prototypes(gids)` that replaces only the affected gids; `gcp` option implements AM&B Algorithm 1 (centroid + farthest points interpolated toward the nearest prototype, `x <- x + alpha (p - x)`). Deviations from the paper: returns exactly K (centroid + K-1 points; the paper's loop gives N + 1), cosine distance, re-normalised, alpha = 0.5 (paper does not state it). (refs: B12, B14, W; AM&B Alg. 1)
- [persistence] v1: gallery lived in RAM/pickle/Pinecone namespace, save wiped the namespace (B13-B15) -> v2: samples table (`samples(id, tracklet_id, frame, quality, in_gallery)`) + `body_samples` vectors, galleries are rebuilt from them on `IdentityEngine.__init__`; runs accumulate across sessions and a reload yields identical decisions (tested). DB schema v2 (migration from v1 is automatic: new tables only). (refs: B5, B13, B14, B15)
- [search] v1: Pinecone top-k, softmax x15 on top-2, face search without margin, face silently overrode body in "both" -> v2: local `body_proto` / `face_tracklet`; body ratio `exp(temp*(s1-s2))` with temp 10, `tau` 1.5 (v1 function default; UI slider was 2.0); face AMBIGUOUS when the runner-up is within `face_margin`; `NO_FACE` when none found; "both": face MATCH wins, body is the fallback, and `SearchHit.modality` says which decided; gid returned as `int`; every MATCH/AMBIGUOUS carries the journey. Falls back to `body_tracklet` if prototypes were never built. (refs: 1.13, 1.14, B12)
- [analytics] v1: Mongo sightings with meaningless timestamps -> v2: `journey`, `transitions`, `dwell_stats`, `occupancy`, `run_summary` as pure functions over the DB (per-stage fps is not derived here). (refs: B1, B2)
- [CLI] new: `reid search --image X [--mode body|face|both] [--crop]` (JSON on stdout, exit 0 for MATCH/AMBIGUOUS, 3 otherwise). `build_parser` got a 2-line hook (`func.add_arguments(p)`) so a command can declare its own options.

### Deviations from the plan / paper worth knowing

- Diversity gate reference: PLAN section 3.3 reads `D(C_i)` as the class's *mean* nearest-neighbour distance; the paper's Eq. 6 is the *minimum* pairwise distance. Default is the paper (`min`); `mean` is available. With iid Gaussian samples `min` fills a budget-50 gallery slowly (300 samples -> 30 members) and `mean` much slower (16); real, correlated tracklet samples are less extreme but galleries stay small and diverse.
- UDM `l = 20` counts samples; a tracklet has <= 16, so online minting after bootstrap needs two or more pooled tracklets of the same appearance (or the flush).
- `IdentityEngine.__init__` takes an optional 4th argument `cameras: CameraSet | None` (topology cannot-links need it); the PLAN signature is otherwise unchanged.
- Samples that the gate rejects stay in `body_samples` (label = gid, `in_gallery = 0`) so a split or rebuild can re-run the gate.

## P2: models, tracker, TrackletBuilder, extraction pipeline, virtual cameras, presets

Scope: `src/reid/models/*`, `src/reid/tracking/*`, `src/reid/pipeline.py`, `src/reid/virtual_cams.py`, `reid process` / `reid virtual-cams`, `configs/presets/*`, preset support in `load_config`, `pyproject.toml` pins, LICENSE. Environment: Python 3.12 venv, torch 2.14.1+cu126 (works on the GTX 1050, sm_61), ultralytics 8.4.218, boxmot 26.0.0, rfdetr 1.12.1, insightface 2.1, onnxruntime-gpu 1.32.0, gdown 5.2.2.

### Behavioural changes

- [body ReID weights] v1: CLIP-ReID ViT-B/16 trained on **Market-1501** (`clip_market1501.pt`, via boxmot <= 17) -> v2: the official **MSMT17** ViT-B/16 checkpoint ("ViT-CLIP-ReID" row of the Syliz517/CLIP-ReID README, Google Drive id `1BVaZo93kOksYLjFNH3Gf7JxIbPlWSkcO`, 1041 classes confirmed in the file), downloaded with gdown to `~/.cache/reid/weights` (or `paths.weights_dir`); URL overridable with `body_reid.weights_url`. Why: MSMT17 is the more diverse training set (cross-domain loss from Market is about -40 mAP points, model_comparison 4b); the weights file itself was not used by v1. Not verified: that this checkpoint is the SIE-free variant is inferred from the checkpoint having no `cv_embed` key and loading strictly. (refs: model_comparison 4, v1_review 1.4)
- [body ReID implementation] v1: boxmot's bundled CLIP-ReID wrapper, called with a list of crops (a signature that does not exist in boxmot 16/17, review 1.4) -> v2: own inference-only re-implementation (`models/clipreid_net.py`) of the official `VisionTransformer` + the two BatchNorm necks, with parameter names identical to the checkpoint. `open_clip` / the `clip` package were **not** used: the official image tower is a modified CLIP (16x8 position grid, returns the block-12 cls token and its projection), so neither package reproduces its keys or forward. Loading asserts zero missing/unexpected keys for `image_encoder.*`, `bottleneck.*`, `bottleneck_proj.*` and that the only dropped keys are `classifier*`, `prompt_learner*`, `text_encoder*` (training-only). `nn.MultiheadAttention` is replaced by `scaled_dot_product_attention` over the same parameters (unit test checks equality to `nn.MultiheadAttention`). (refs: W1, review 1.4)
- [body ReID feature] v1: 1280-D = `cat(BN(cls768), BN(proj512))`, L2-normalised -> v2: same by default (`body_reid.neck_feat: after`). **Deviation to be aware of**: the official repo's test config uses `NECK_FEAT: 'before'` (raw cls and projection, no BN), which is what its published mAP numbers use; we keep `after` for v1 parity. Measured on 73 crops of 8 tracks in the smoke clip: `after` same-person cos 0.82 vs different-person 0.23, `before` 0.95 vs 0.78 (both separate perfectly, but `before` compresses cosine scores, which would invalidate v1-style absolute thresholds like `min_cos` 0.78). Option kept for evaluation in P6.
- [body ReID preprocessing] v1: stretch to 256x128, BGR->RGB, `(x-0.5)/0.5` -> v2: identical for CLIP-ReID (matches the official config: `PIXEL_MEAN/STD` 0.5, size 256x128); OSNet uses ImageNet mean/std. Crops are batched (`runtime.batch_size`) and embedded across tracks and frames, not per frame, and only for gated samples. fp16 is auto-disabled on GPUs below compute capability 7 (GTX 1050: no fast half).
- [tracker] v1: BotSort constructed with a **second CLIP-ReID encoder** running on every detection every frame (W1), a 404-ing weights workaround, and `tracker.update` skipped on empty frames (W12) -> v2: boxmot 26 tracker (bytetrack / botsort / occluboost) in motion-only mode (`use_embeddings=False`, no ReID model is ever loaded by the tracker), `update` called on every processed frame including empty ones, one fresh tracker per camera. Parameter mapping to boxmot 26 names is in `tracking/tracker.py` (`track_buffer` -> `max_lost_frames`; `occluboost` keeps its tuned defaults). Wrapper returns `(track_id, box, conf, det_index)` so each track keeps the keypoints of the detection that produced it. (refs: W1, W12, review 1.2)
- [detector] v1: RT-DETR-L (`rtdetr-l.pt`), conf 0.25 -> v2: preset-dependent (balanced default YOLO26m-pose single model; RF-DETR S/M/L and RT-DETR still supported), conf default unchanged at 0.25. RF-DETR: **verified on rfdetr 1.12.1 that predictions carry 1-indexed COCO ids (person = 1) while `model.class_names` is a 0-indexed list (person = 0)**; we select by the per-detection class name, fallback id 1. (refs: model_comparison note on RF-DETR ids)
- [pose gate] v1: pose model run on all gated crops, `keypoints.data[0]` = whichever person the model ranked first in the crop (W12) -> v2: (a) single-model mode: the keypoints are the detector's own output for that box (det_index match); (b) two-model presets: pose on padded crops (`quality.pose_pad` 0.15), and for each crop the pose is chosen as the one whose box contains the target box centre with the largest IoU against the target, else zeros (visibility 0, sample rejected). The choice is unit-tested (neighbour listed first, centre test, overlap preference). Quality = visible-keypoint ratio x detection confidence, as in v1. Note: the 5 head keypoints still count like the others (v1 weakness unchanged). (refs: W12, review 1.3)
- [sampling] v1: every gated track every frame went through pose + CLIP -> v2: at most one sample per track every `sample_every` (5) **processed** frames, after cheap gates in this order: detection conf >= `min_det_conf`, box height >= `min_box_h`, not truncated at the frame edge (`edge_margin_px`), then keypoint visibility >= `min_visible_ratio` and quality >= `min_quality`. Per-reason rejection counts are logged and returned in `CameraStats.rejects`. Top `max_samples_per_tracklet` (16) by quality are kept; best-quality crop kept separately (not v1's "last crop"). (refs: PLAN 3.1, W12)
- [min_det_conf calibration] v1: 0.75 (RT-DETR-L confidences) -> v2: default still 0.75, but the **lite preset sets 0.5**: on the smoke clip with YOLO26n-pose 0.75 rejected nearly every due sample (185 and 451 rejections, 93 samples in total), at 0.5 there were 141-161 samples. Not tuned for the other presets (YOLO26m/RF-DETR scores were not calibrated against it).
- [face pairing] v1: full-frame `face_app.get(frame)` every frame, `det_size` 640, pair by centre in head region, m6 took the **first** candidate (B18) -> v2: face detection only for accepted body samples of `is_face_cam` cameras, run on the head-region crop (top `head_region` 40% of the body box + 10% margin) so one face cannot pair with two bodies; among faces with score > `face.det_conf` and centre inside the head region the one with the highest **quality** (det_score x size factor x frontalness) is kept. Top `max_faces` per tracklet; best face crop saved with `crop_margin`. (refs: B18, review 1.5)
- [face quality] v1: `det_score` only -> v2: `det_score x size x frontalness`; size = 0 at `min_face_px` (32) rising linearly to 1 at `full_size_px` (112); frontalness from the 5 landmarks: yaw (nose offset from eye midpoint / inter-ocular distance, 0 at >= 0.5) times a mild pitch term (nose position between eye and mouth line). The thresholds are heuristics I chose, not taken from a paper.
- [face runtime] v1: `ctx_id=0` regardless of the embedding device, always loaded -> v2: loaded only when `face.enabled`; GPU used only when the device is CUDA **and** compute capability >= 7. onnxruntime-gpu 1.32 fails in `cublasCreate` on the GTX 1050 (verified), so the faces run on CPU there (about 270 ms for a 6-face image with buffalo_sc); a failure on CUDA falls back to CPU instead of crashing. `embed_aligned(chip)` keeps v1's gray padding (`search.face_pad` x max(h, w) on each side, the 3x canvas for square chips) and returns None if no face is found; embedding of a cropped face vs the same face in the full image: cos 0.92 on an InsightFace sample.
- [tracklet lifetime] v1: sightings closed only at end of video, no final flush (B2, B8) -> v2: a tracklet is finalized when its track has not been seen for `track_lost_s` (2 s, measured in video time, so it is stride-independent), or at the end of the video; tracks with < `min_points` (5) boxes are dropped as flicker; tracklets with fewer than `min_samples` samples are still stored (gid NULL, P3 decides). Pending embeddings are flushed before any tracklet is finalized. (refs: B2, B8)
- [track points] v1: only the best crop's box was stored (`best_crop_bbox`, review 4) -> v2: every tracker output box is stored (`track_points`), with `sampled=1` on the frames whose sample survived top-K. Frames where the tracker returns nothing for a (lost, buffered) track have no point. (refs: PLAN 0)
- [timestamps / fps] v1: fps 30 hard-coded (m4) or wall-clock start (m6) -> v2: `ts = camera.start_ts + frame_index / fps` with fps from `cv2.CAP_PROP_FPS` (CameraSpec override), frame_index = index in the source video (so `frame_stride`, `start_s` do not shift time). (refs: B1)
- [pipeline] v1: one monolithic notebook loop per video -> v2: `pipeline.run(cfg, cameras, engine=None, progress=None, *, models=None, conn=None)`; cameras sequential in one run; per camera: upsert camera, extract, insert each finalized tracklet with its points (`db.insert_tracklets`), write the best crops/faces under `data_dir`, then `engine.on_tracklet(t)`; `engine.end_camera(cam)` after each camera and `engine.end_run(run_id)` at the end. Run status becomes `failed` on exception. `RunResult` has per-stage ms/frame (read, detect, track, pose, reid, face), wall fps, per-camera counts and torch VRAM peaks per stage. Crop paths are written with a raw `UPDATE tracklets` in `pipeline.py` because a path needs the tracklet id and `storage/db.py` (shared with P3) was not touched.
- [CLI] new: `reid process --cameras X.yaml [--preset P] [--no-identity] [--set k=v]` (identity association via `IdentityEngine` from `reid.identity`; falls back to extraction-only with a warning if the import fails; JSON result including `run_summary` on stdout); `reid virtual-cams VIDEO --out-dir D [--n --overlap --mirror --delays --width --start --end --face-cams --yaml]`. `--preset` is a common option of all commands. Config precedence: defaults < preset < `-c` file < `--data-dir`/`--set`.
- [virtual cameras] new: N horizontal crops with exact overlap (`overlap` x crop width, first crop at x=0, last ends at the frame edge), optional mirror, per-camera delay (written as the camera's `start_ts`, i.e. the same clip appears later on the shared timeline), downscale via ffmpeg (OpenCV fallback). It proves the plumbing, not cross-view generalization: both views share lighting/optics and the overlap region is the same pixels. Left/right halves with 15% overlap of the smoke video give an **empty left camera** (it frames the shop front) - use `--overlap 0.6` to get people in both.
- [config] model defaults replaced by the balanced preset (`yolo26m-pose.pt`, single-model, `botsort`, `clipreid_msmt17`, `buffalo_l`); `configs/presets/{lite,balanced,accurate,max}.yaml` added; new keys `paths.weights_dir`, `quality.pose_imgsz/pose_pad`, `body_reid.weights_url/neck_feat`, `tracking.use_cmc`; `quality.pose_model` is now nullable (null = detector keypoints); `tracking.tracker` is a Literal; removed `tracking.with_reid` (v1 behaviour that is gone by design). `configs/default.yaml` regenerated. `max` preset: PersonViT-B is **not** wired (no weights integration in P2, license unchecked); it uses CLIP-ReID and antelopev2 (AdaFace not wired).
- [packaging] `models` extra pinned to the installed, verified versions; `uv` overrides drop `opencv-python` (pulled by ultralytics) and `onnxruntime` (pulled by insightface) because they overwrite `opencv-python-headless` / `onnxruntime-gpu` files; AGPL-3.0-only LICENSE added; wheel ships `configs/presets` as `reid/presets`; pytest default skips `-m models`.

### Measured on this machine (GTX 1050 3 GB shared with a running game that held ~1.8 GB of VRAM and ~2 CPU cores, so numbers are pessimistic)

- Smoke (`store_cam3.mp4`, first 6 s, 2 virtual cams 960 px wide, 24 fps), `--preset lite`, extraction only: 288 frames in 13.8 s = 20.8 fps; ms/frame: read 1.9, detect 37.2, track 2.1, reid 6.6, pose 0 (single model), face 0 (no face camera); torch VRAM peak 150 MB (detect 78 MB, reid 150 MB, both include resident weights); left camera = 0 tracklets (no people in frame), right camera = 16 tracklets, 1038 track points (65 per tracklet), 161 samples (mean 10, min 1, max 16 per tracklet, 15/16 tracklets have >= 2).
- Same with identity engine on `--overlap 0.6 --mirror 1` cameras (`min_det_conf` 0.5): 17 tracklets, 10 identities, 88% of tracklets identified, mean 1.5 tracklets per identity, 2 unidentified (< 2 samples); gids 1-3 span both cameras. The ground truth number of people is unknown, so identity accuracy is **not** measured.
- `--preset balanced` (YOLO26m-pose, BoT-SORT, CLIP-ReID, buffalo_l) on 3 s of the 2 overlapped cameras: no OOM, 5.7 fps, detect 107 ms/frame, reid 60 ms/frame, torch VRAM peak 560 MB (CLIP-ReID stage); face model on CPU.
- Two-model path, `accurate` with RF-DETR-Small + YOLO26s-pose on crops + OSNet (2 s, same cameras): 5.3 fps, detect 132, pose 31, reid 14 ms/frame, VRAM peak 397 MB. RF-DETR-M/L, `max` and OccluBoost were not run end to end (OccluBoost was only exercised on synthetic boxes).
- CLIP-ReID sanity (73 crops, 8 tracks from the smoke clip, same-track pairs >= 12 frames apart vs co-visible different-track pairs): CLIP-ReID after-BN same 0.822 / different 0.233, AUC 1.000, rank-1 over other frames 1.000; OSNet same 0.854 / different 0.479, AUC 0.999, rank-1 1.000. Tracks come from the tracker (no manual labels) and the crops are from the upper half of the frame (the lower half of this source file has decode corruption), so this is a sanity check, not an accuracy figure.

### Not verified / open

- Faces end to end on a real face camera: the smoke video is a top-down mall view with no usable faces. Verified only: `FaceModel.analyze/embed_aligned` on an InsightFace sample image and the builder's face selection with fake detections.
- The `max` preset's PersonViT / AdaFace, RF-DETR-M/L, OccluBoost on video, `runtime.fp16` on a Volta+ GPU, onnxruntime on a CUDA >= 7 GPU, Colab.
- `quality.min_det_conf` / `sample_every` / `min_box_h` defaults are v1 values and are not re-tuned for YOLO26 and small (960 px) frames.
- ByteTrack/BoT-SORT parameters (`track_high_thresh` 0.5, `match_thresh` 0.8, `track_buffer` 30) are v1 library defaults mapped to boxmot 26 names; boxmot 26's own defaults differ (e.g. BotSort `max_lost_frames` 40).
- RF-DETR downloads its weights to `~/.roboflow/models`, not to `paths.weights_dir`.
- The source video `store_cam3.mp4` has H.264 decode errors in the lower part of many frames (ffmpeg warnings); virtual cameras inherit them.
- Detector input for RF-DETR ignores `detection.imgsz` (native resolution per model size).

## P4: visualization (render, mosaic, follow-person, timeline, heatmaps)

### Behavioural changes

- [evaluation] v1: "evaluation" re-queried the system's own saved best crops against prototypes built from the same crops (circular, W4), 85.35% body accuracy on 1,317 crops, no tracking or cross-camera metric -> v2: `reid evaluate --data-dir D --gt gt.csv [--iou 0.5] [--run-id N] [--min-gt-height 40] [--queries-per-id 5] [--no-retrieval]` (`src/reid/eval/`, extra `[eval]`). Reports (1) per-camera MOT metrics with `motmetrics` (IDF1, MOTA, ID switches, precision, recall, FP, FN) from `track_points`, hypothesis id = gid (an unidentified tracklet gets a unique negative id), and a second table with hypothesis id = tracklet id (tracker only, separates tracking from identity association); (2) the **CityFlow-style combined IDF1**: one accumulator over all cameras, frame key = (camera, frame) encoded as `camera_index * 10**7 + frame`, GT ids global, hypothesis ids = gids, so a gid that spans cameras must match ONE GT person globally (2D-box IDF1 in the spirit of the AI City cross-camera identity protocol, not the official 3D-location HOTA, so not comparable with the leaderboard); (3) fragmentation/purity from the matched (GT id, gid) box counts (GT people split over >1 gid, gids covering >1 person, box-weighted purity and completeness; a link needs >= 10 matched boxes and >= 5% of the person's/gid's boxes); (4) held-out retrieval. Output: markdown on stdout and `data_dir/eval/<timestamp>.json` with the run's stored config, the preset (inferred from the model choices of the run unless `--preset` is given) and the protocol parameters.
- [retrieval protocol] v1 circular -> v2: queries are GT boxes cropped from the video (5 per GT person, spread over cameras and time, >= 80 px tall, not touching the frame edge); a box is held out if no stored body sample of the same camera lies within 10 frames at IoU >= 0.3 of it (if a person lacks held-out boxes the rest is filled with non-held-out ones; the share held out is reported). A gid's identity is its majority GT id; Rank-1/Rank-5/mAP are computed on the ranked gids (`body_proto`, else `body_tracklet`), and `search_body` (with its MATCH/AMBIGUOUS/UNKNOWN thresholds) is run on the same embeddings (answered share and precision). GT people that no gid represents are reported as unretrievable and excluded. Limitation: held-out frames still belong to a tracklet that contributed other samples, so this measures generalization to unseen views of a known tracklet, not a disjoint gallery; read it together with fragmentation.
- [frame filter] GT is compared only on frames the run processed (`runtime.frame_stride`, `start_s`, `end_s`, `max_frames` read from the run's stored config) and GT boxes shorter than `--min-gt-height` (40 px at the processed resolution) are ignored.

Per camera IDF1 (gid hypothesis / tracker only), `lite` 120 s: cam_0700 94.8 / 76.5, cam_0701 71.4 / 51.2, cam_0708 98.8 / 98.8, cam_0711 92.9 / 63.8. `balanced` 60 s: 95.0 / 75.6, 85.0 / 72.9, 98.8 / 98.8, 98.6 / 81.2. Retrieval: 50 queries (90% held out) for the 120 s run, 35 queries (80-86% held out) for the 60 s runs; `search_body` answered 47/50, 32/35 and 27/35 queries, all answers correct (100% precision).

Observations (one synthetic scene, 7-10 people, so indicative only):
- **Cross-camera association works** on this scene: no gid merges two people in any run (purity 100%), only 1 of 10 people is split across two gids with `lite` (mean 1.10 gids per person, GT completeness 99%), none with `balanced`. The combined IDF1 is limited by recall (IDR 73-87%), not by identity errors (IDP 97-98%). Caveat: the people are synthetic with distinct appearances, so this validates the plumbing and constraints, not absolute ReID thresholds.
- **Tracking does break, and the identity layer repairs it.** The tracker alone fragments tracks (44 tracklets for 10 people over 4 cameras; tracker-only IDF1 51-77% on the busy cameras versus 71-95% with gids), and gid assignment merges those fragments back (per-camera IDF1 with gids is +20 to +30 points on cameras 0701 and 0711).
- **The dominant error is detection recall on small people, not association.** Recall by GT box height (ad hoc script, not part of `reid evaluate`; lite, 120 s): >= 200 px 98.6%, 120-200 px 78.8%, 80-120 px 5.7% (cam_0701: 3.1%), 40-80 px 13.2%; `balanced` (YOLO26m, 60 s): 99.3%, 94.0%, 39.7%, 31.7%. People are small in the 720p frames and the detector sees 640 px inputs (`detection.imgsz`), so a 100 px person is about 50 px. This explains FN 2115 on cam_0701 with `lite` (56.7% recall) and is the first thing to look at when tuning (imgsz, detector size, `min_box_h`), not done in this phase.
- Held-out retrieval is near ceiling (Rank-1 97-98%, mAP 98%) and cannot discriminate between presets here; it is not comparable with v1's 85.35% (different data, held-out protocol). Rank-5 of `balanced` 97.1% vs 100% for `lite` is one query.
- Per-camera IDF1 with gids does not penalize an unidentified tracklet that is tracked consistently (its negative id is a consistent id inside one camera); the combined IDF1 and `matched boxes unidentified` do.

## P7 fixes

- [tracking] v1: BotSort ran with its own appearance model (OSNet x0.25 in m4, a second CLIP-ReID Market in m6) -> v2 (P2): motion-only (W1, efficiency) -> P7: that regressed. When two people cross, the motion-only tracker sometimes swaps them, so one tracklet contains person A and then person B; the tracklet-level identity layer cannot undo that (it saw one blended embedding, assigned one gid and sometimes created a duplicate identity). Measured on AI City scene 075 with the new metric: 2 of 54 tracklets mixed two GT people. Why: fixed in two layers below.
- [tracklets] v1: n/a -> v2: `TrackletBuilder` keeps the chronological history of every embedded sample (with a JPEG of its padded crop) and, per point, the max IoU with other tracks of the same frame. On finalization a tracklet is split where the appearance changes abruptly: best change point `k` minimising cos(mean(e[:k]), mean(e[k:])) with at least `split_min_samples` (3) samples per side, split if below `split_min_sim` (0.7), recursively. The cut frame is the point between the two neighbouring samples with the highest overlap (where people crossed), the middle one among ties (no overlap: the middle of the gap). Each piece is its own tracklet (own top-16 samples, best crop, faces, embeddings; `min_points` applies per piece). Config `tracklets.split_on_appearance` / `split_min_sim` / `split_min_samples`; the per-camera `splits` count is in the `reid process` JSON. Why: calibrated on the AI City run with CLIP-ReID: two halves of one person's tracklet >= 0.88 (median 0.96), different people <= 0.58 (median 0.17), the two halves of the mixed tracklets 0.05 and 0.04.
- [tracking] v1: appearance tracking always on -> v2: optional `tracking.appearance` (default off) and `tracking.appearance_thresh` (0.25, BoT-SORT paper). When on (botsort, occluboost; ByteTrack warns and runs motion-only) the pipeline embeds every detection crop with the body model, passes them to the tracker, and reuses them as tracklet samples (no double embedding). boxmot 26 only takes embeddings through its canonical `Detections` object (the NumPy path cannot carry them) and builds its own ReID model only when none are supplied, so none is loaded. Why: costs one body embedding per detection per processed frame, so it is a choice, not the default.
- [eval] new metric `tracklet_purity` (tracklets matched to >= 2 GT people with >= 5 boxes each, and the box-weighted purity), listed in `reid evaluate` under "Fragmentation and purity". Why: box-level metrics barely notice a short swap, but it is what a user sees as "person 1 is two people".
- [tracklets] `max_history` (400): the per-track sample history is thinned (older half at half density, best sample kept) beyond this, so memory stays bounded for people in view for hours.
